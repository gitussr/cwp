WIRE PROTOCOL

TCP hands you a stream of bytes with no idea where one message ends and the next begins. CWP is a small application protocol built on top of that stream — length-prefixed binary framing, session handshakes with replay-proof sequence numbers, and CRC-32 integrity checks — implemented in TypeScript, with a test suite that tries to break it before anything else does.

§1

The problem

A raw TCP socket doesn't know what a "message" is. It only knows bytes.

Write HELLO then WORLD to a socket and the other end might see HELLOWORLD in one read, HE then LLOWORLD in two, or anything in between — TCP is free to split or coalesce your writes however it likes. Every protocol built on top of TCP, from HTTP down to whatever your database driver speaks, has to solve this exact problem before it can do anything else.

I'd already explored a handful of ways to solve it — twelve small throwaway scripts, still in /archive on the repo — and every one of them worked, right up until it didn't:

  • Delimiter framing broke on its own delimiter. Splitting on ; or | corrupts the moment a payload legitimately contains that character.
  • No cap on an announced length. A malformed length prefix could tell the server to buffer gigabytes before rejecting anything.
  • A session timer that never got cleared. setInterval with no matching clearInterval — fine in a long-running server, a leak in anything short-lived like a test.
  • A checksum that wasn't actually checked against a tamper case — corruption during transit went undetected.
§2

The design

CWP/1 fixes each of those, as one coherent protocol instead of four separate lessons.

  • Binary length-prefixed framing — a 4-byte outer length says exactly how many bytes make up the frame, so the body can contain any bytes at all, delimiters included.
  • A hard frame-size ceiling — checked the instant the length prefix arrives, before a single byte of the body is buffered.
  • Sessions with replay-proof sequencing — a handshake opens a session; every command must carry exactly lastSeq + 1, or it's rejected.
  • CRC-32 integrity checks on every frame, via Node's own zlib.crc32 rather than a hand-rolled checksum.
  • A promise-based client that correlates responses back to requests by sequence number, so concurrent in-flight commands resolve to the right result even when pipelined.

The wire format itself lives in src/protocol/ and doesn't import node:net at all — parsing a frame is pure buffer-in, frame-out logic, testable in microseconds without a real socket. src/server/ and src/client/ are the only places that know what a session or a command actually means.

Using it

Runs directly from TypeScript source — no build step, no bundler:

$ git clone https://github.com/gitussr/cwp.git && cd cwp/cwp
$ npm install          // two dev deps: typescript, @types/node
$ npm test             // node:test — 47 tests, unit + real-socket integration
$ npm run server       // starts a CWP server on :5000
$ npm run client       // runs a client against it

The public API is a small, typed surface:

import { CwpClient } from "./src/index.ts";

const client = new CwpClient({ host: "127.0.0.1", port: 5000 });
await client.connect();
await client.handshake();

await client.sendCommand("ECHO", "hello");   // → "hello"
await client.sendCommand("TIME");            // → ISO timestamp

Why this project

Most fullstack work never touches the layer underneath HTTP — I wanted to actually build it, not just consume it.

Frameworks handle framing, backpressure, and message boundaries so well that it's easy to go years without thinking about them. I picked this project specifically because it forces those problems into the open: what does socket.write() returning false actually mean, what happens when a chunk splits a message in half, how do you stop a hostile length field from taking down a server.

It's also deliberately AWS-adjacent. A session store that's just an in-memory Map works great on one instance and falls over the moment there's a second one behind a load balancer — the exact reason DynamoDB and ElastiCache exist. A background sweep that evicts idle sessions is a hand-rolled version of a DynamoDB TTL attribute. Closing every open socket on shutdown, not just refusing new ones, is connection draining — the same distinction between an ALB deregistering a target and an ECS task actually finishing in-flight work before SIGKILL. Building the small version by hand made the managed version make sense.
